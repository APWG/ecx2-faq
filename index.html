Frequently Asked Questions (FAQ)

  1. Are all data records the same?

    No. Every record contains a representation of how confident the person who submitted that data is of its maliciousness. The confidence field is one of four values:

    • 100 CF = Manual inspection/confirmation by an APWG member reporter, submitting data under terms set out in the APWG Data Sharing Agreement.

    • 90 CF = Automated inspection/confirmation by Artificial Intelligence or Machine Learning systems directly curated by an APWG member submitter, under terms set out in the APWG Data Sharing Agreement.

    • 50 CF = Machine data-capture or third-party volunteered report without confirmation by APWG member personnel or by a member-curated AI/ML.

      The assumption is that the record has a 50/50 chance of being accurate, therefore requiring user confirmation.

    • 0 CF = False positive. We never remove data from the eCX, just remark it.

  2. How do I mark a data record as a false positive?

    False positives have a confidence value of 0 (zero). Find the record you wish to modify, double click it, change the confidence to 0, and click update.

  3. I can’t find the data I’m looking for.

    There are two very different scenarios in this answer. First, people blame the APWG for everything. It’s possible that we don’t have the bad data in our database. If you are sure we have the data send a message to support@ecrimex.net and we’ll investigate. Most common is that the database searcher is confused. We have seen this happen with multiple “.” or “-“ in a domain name. For a URI, start with the http:// or https:// adding the domain name a little slower as the searching function researches on every key stroke.

    We have also experienced searching failures when your local web browser has been "updated" but not "restarted". (Really.)

  4. Can I get another user invited to the eCX?

    Yes, membership comes with multiple users. Request an invitation via the our admin or support addresses. Likewise, please advise if one of your users has left your operation team or employment so we can reduce the likelihood of an inactive account being breached.
